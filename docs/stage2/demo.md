## 启动

项目根目录：先`npm ci`，再`npm run build`，最后`python3 server/app.py`。浏览器打开 http://127.0.0.1:8765 。Python 3.10+、Node 20.19+/22.12+；本机实际使用Python 3.9也通过当前测试，但交付建议3.10+。

需要改Vue时：一个终端运行`python3 server/app.py`，另一个运行`npm run dev`，打开5173端口；Vite会转发/api。

## 约5分钟的展示顺序

1. **范围与两个功能（30秒）**：展示用况图，说明分析范围为资料收集和作业辅导，当前实现为资料收集及看板。后三个页面明确是原型。
2. **分析与设计（90秒）**：课程→资料→历史版本；来源属于各版资料，学生完成状态独立。导入控制器先全量校验，再事务保存。辅导设计中任务固定材料快照，模型只产草稿，人工决定独立记录。
3. **实际功能（2分钟）**：先在课迹资料页复制连接码，在Chrome教学网课程页面点导入助手采集，核对三类计数后确认导入；回到课迹刷新，展示通知、作业要求、附件目录；再采集同一课程，观察未变化计数。看板展示截止冲突和两种依据。完成状态仅用于本地跟进，不声称教学网已交。
4. **异常和测试（30秒）**：把截止改为无时区值，整批拒绝且原资料不受影响。展示`npm test`20项通过和`npm run build`成功。
5. **进度与Git（30秒）**：展示`git show --stat HEAD`、本地分支、历史提交及progress.md。明确当前未推送/未提交课程材料，组员历史贡献由小组核对。

## 可直接使用的开场

我们这一阶段分析了课程资料收集和作业辅导两个核心功能，重点实现资料收集。第一阶段的页面使用预设数据，这次改成从实际输入读取资料，校验来源后保存到本地数据库，看板和资料页读取同一份数据。现在由Chrome导入助手读取已登录课程的通知、作业和课件目录，学生预览确认后保存；手动输入保留作补充。

## 设计讲解要点

资料收集最容易出错的是来源、版本和学生状态混在一起。因此每份资料保留来源定位和版本，重复导入不新增，内容变化才增加版本，学生是否完成不随资料覆盖。作业辅导进一步固定材料快照，生成器只读这些材料，确定性规则检查引用和结果结构。确认与退回由网页记录，模型不能替学生决定。

## 问答准备

- **是否已接教学网？** 已实现浏览器侧用户触发的课程采集。登录由学生完成，采集只读，不导出Cookie、不后台定时运行。课件只导入目录和链接，不等于已下载附件正文。
- **用了什么面向对象设计？** 分析层按领域责任识别Course、Material、版本、SourceRef、Deadline；设计层把校验、控制和仓储分开。不是把每张表都机械写成一个类。
- **AI辅导能现场生成吗？** 不能。目前完成分析设计，界面为原型。本阶段已实现的核心功能是资料导入与管理。
- **状态会丢吗？** 资料、版本和截止状态在SQLite，刷新/重启保留；原型页仍使用浏览器本机状态。
- **为什么不直接公网部署？** 当前单用户本机版本没有登录和课程授权；多人部署需要补这些能力。
